# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Read the README first

`README.md` is accurate and current. It documents the architecture, the provider adapter contract, the per-adapter API quirks, and the HTTP API. This file covers only what the README doesn't: cross-file invariants and conventions you'd otherwise have to reverse-engineer.

## Commands

```bash
npm install
npm start        # node server/index.js — the ONLY script; serves API + static frontend on PORT (default 3000)
```

There is no build step, no bundler, no linter, and no test runner. `public/` is served as-is; editing frontend files needs only a browser refresh. Server changes need a restart (no watch mode).

Node 26 / ESM (`"type": "module"`) — use `import`, not `require`, everywhere.

## Verifying changes

There are no automated tests. The Mock provider is the verification path: it needs no API key, returns `isConfigured() === true` unconditionally, and streams canned turns word-by-word, so a full debate exercises the entire turn loop, SSE fanout, and frontend render path offline and for free. To verify a change, run `npm start`, set **both** agents to **Mock (offline demo)**, and run a debate.

Two gotchas when doing this: the setup form preselects the first *configured* provider, which is a real (billed) one if `.env` has keys — always pick Mock explicitly. And for scripted browser verification, `playwright-core` driving the system Chrome (`chromium.launch({ channel: 'chrome', headless: true })`) works with no browser download.

## Vocabulary: turn vs. round

These are easy to conflate and the codebase is not internally consistent about them.

- A **turn** is one statement by one agent. `config.maxTurns` counts statements (2–20), and `session.turn` indexes them. Agent A speaks even turns, Agent B odd (`speakerIndex = turnIndex % 2`).
- A **round** is a pair of turns. Rounds are derived, never stored: `Math.ceil(maxTurns / 2)`.

The UI's statement meta bar labels each statement `Turn ${Math.floor(turn / 2) + 1}` — that is the *round* number, so two statements share a label. But `exportMarkdown()` labels the same statement `Turn ${entry.turn + 1}` — the statement number. The Markdown export and the on-screen label therefore disagree for every statement after the first. Know which one you're touching before you "fix" either.

Moderator entries are neither: they carry `afterTurn` (a statement index) instead of `turn`, and their "after turn N" label — on screen and in the export — is the *statement* number (`afterTurn + 1`), deliberately matching `exportMarkdown()` rather than the round-numbered on-screen label of agent statements.

## Cross-file invariants

**Stance presets are scenario-scoped and live only in `server/prompts/`.** Each scenario module owns its own `stances` array; there is no global `STANCE_PRESETS`. The frontend fetches the whole roster from `GET /api/scenarios` at startup (`loadScenarios()` in `public/app.js`), picks one by `?scenario=<id>`, and builds the dropdown from that scenario's list — so adding or rewording a preset stays a one-file change. `public/app.js` keeps only a `custom`-only fallback used when that fetch fails. Nothing in the frontend may hard-code a preset `id`: Agent A defaults to the first non-custom preset and Agent B to the second, whatever the active scenario lists — which is what lets `socratic` ship `teacher`/`student` where the debate scenarios ship `supporter`/`adversary`. The frontend still sends resolved stance *text* to the server (`resolvedStance()`), so the `text` field is what actually reaches the prompt; the server separately stores `config.scenarioId` and resolves the module itself.

**`classroom-debate` is the default and must stay a byte-for-byte no-op.** `getScenario()` falls back to it for an unknown id rather than returning `undefined`, because `?scenario=` is user-typed and `config.scenarioId` is replayed from sessions — throwing inside the turn loop would surface as a mysteriously paused debate. Its four prompt functions are copied verbatim from the pre-split `server/prompts.js`, down to a trailing space on one rules line. A debate started with no `?scenario=` must behave exactly as it did before scenarios existed; if you reword that scenario, you are changing the product's default, not refactoring.

**The Mock provider parses the stance text, so every scenario must keep `Your assigned analytical stance: <text>` on a line of its own.** `mock.js`'s `poolFor()` regex-matches that line out of the system prompt to pick its skeptic vs. defender voice. Three things are coupled: a scenario's stance wording, its `buildSystemPrompt()` phrasing, and the mock's keyword regex — reword any of them and the mock, your only verification path, can fall through to its length-parity fallback and give both agents the same voice. The `socratic` scenario is the cautionary case: its hand-written source ran the marker inline (`...and your assigned analytical stance is: X. If your stance is that of the teacher...`), and the single-line capture then swallowed both "teacher" and "student" for *both* agents. The fix was splitting the line, not relaxing the regex — do not "generalize" that pattern to accept inline variants. `poolFor()`'s keyword sets also carry teacher/student terms so a tutorial run still gets two distinct voices, even though both pools are debate prose.

**The turn-visual prompts are shared across scenarios, deliberately.** `server/prompts/visuals.js` is art direction and composition — how a figure is drawn, not what the conversation is about — so it sits outside the scenario contract and `server/debate.js` imports it directly. `buildVisualDirectorPrompt()`'s opening line does say "classroom debate about the paper", but the archetypes are argument-analysis moves and they are what the director actually reasons over. If a scenario ever needs its own director, give the scenario object an optional `buildVisualDirectorPrompt` and have `_generateVisual()` prefer it — but keep the "You are the visual director" opening in every variant, or the `DIRECTOR_MARKER` coupling in `mock.js` breaks.

**`renderStatementHTML()` in `public/render.js` is the only code path allowed to set `.innerHTML` from model output — or moderator-typed text.** It is a small markdown renderer (headings, lists, tables, blockquotes, fenced/inline code, rules, links, bold/italic/strikethrough) built on one invariant: block structure is detected on the *raw* lines, but every fragment that reaches the output has been through `escapeHtml()` first, and the tags are literals chosen by the renderer — never derived from input. Never invert that order, and never interpolate a raw fragment "just this once."

**That renderer is shared with the server, which is why it is its own module.** `public/render.js` is imported by the browser (`public/app.js`) *and* by Node (`server/export-html.js`, which builds the `?format=html` transcript export), so an exported statement is byte-identical to the one on the projector. Two constraints follow. It must stay free of both DOM and Node APIs — its only ambient dependency is an optional global `katex`, which each side supplies differently — so anything DOM-shaped stays in `app.js` (`appendCaret()` is the example: it was deliberately left behind). And `app.js` is loaded as `<script type="module">` purely to make that import possible; it is the one script in the app that is not classic, so nothing may rely on its top-level `const`s being window globals.

**Math is the one documented exception to that invariant.** KaTeX HTML is written to the output *without* passing through `escapeHtml()`, because it is generated by the typesetter rather than interpolated from input — KaTeX escapes every glyph it copies out of the TeX source itself. What makes that safe is `trust: false` in `renderMath()` (`public/render.js`), which is what refuses `\href`, `\url`, `\includegraphics`, and the `\html*` family — the only macros that can emit a URL or raw HTML. Never set `trust: true`, and never route model text to any KaTeX entry point other than `renderMath()`. `renderMath()` returns `null` when the vendored library is missing, and every call site falls back to rendering the math as literal escaped text, so a missing `public/vendor/katex/` degrades instead of throwing.

Math is lifted out of the text at two points, both chosen so the emphasis regexes can never see inside an equation (`$a * b$` would otherwise become `<em>`). Inline `\(…\)`, `$$…$$` and `$…$` are held out **inside `mdInline()`, after the code-span lift and before emphasis** — that position is what keeps `` `$5` `` in backticks literal for free. Multi-line display math (`\[…\]`, `$$…$$`, and ```` ```math ```` fences) can't be seen by `mdInline()`, which only ever gets one line, so `mdBlocks()` handles it as a block via `renderMathBlock()`; `RE_MATH_BLOCK` is in `startsBlock()` so a `$$` line interrupts an open paragraph. An *unclosed* opener renders as literal text on purpose: while streaming, the opener arrives many tokens before the closer, and typesetting the half-written equation flashes KaTeX's red error text on the projector until it completes. Bare `$…$` also carries currency guards (no space just inside the delimiters, no digit right after the closer, body not just an amount) so `$40 to $60` stays money — reach for `\(…\)` in any new prompt text, since it needs no guards.

Two supporting details are easy to break. `mdInline()` lifts code spans and link hrefs into a NUL-delimited placeholder table before emphasis regexes run, so a `*` inside backticks or a `_` inside a URL is not mistaken for markup — `renderStatementHTML()` strips NUL from the input to keep those placeholders unforgeable. And `safeUrl()` is the only gate on `href`: it whitelists `http(s)://`, `mailto:`, `#`, and relative paths, and a link that fails it renders as literal text rather than a stripped-attribute anchor.

`.stmt-body` no longer sets `white-space: pre-wrap` — the renderer emits real block elements, and a soft newline inside a paragraph becomes `<br>`. Anything that adds a block tag to the renderer needs a matching `.stmt-body <tag>` rule in `styles.css` — and in `DOC_CSS` in `server/export-html.js`, which is a deliberate trimmed copy of those rules for the standalone export — or it inherits browser defaults that clash with the parchment theme. The streaming caret is placed by `appendCaret()` *inside* the last rendered block (not appended after the HTML), so it sits on the text baseline instead of dropping to its own line — but it stops descending at a `.katex` / `.katex-display` root, because parking it inside an equation's span tree shifts the glyphs around it.

**KaTeX is vendored, not installed.** `public/vendor/katex/` holds `katex.min.js`, an unmodified `katex.min.css`, and woff2 fonts only; `express.static` serves it with no route change, and `public/vendor/katex/VERSION` records the version and how to update. `index.html` loads the stylesheet *before* `styles.css` (so `.stmt-body .katex*` rules win) and `katex.min.js` before `app.js` — the former is a classic non-deferred script, the latter a deferred module, so the global `katex` is always defined by the time any statement renders. The server gets the same library a stranger way: `ensureKatex()` in `server/export-html.js` runs the vendored file's source through `new Function('module', 'exports', src)` and assigns the result to `globalThis.katex`, because `"type": "module"` makes Node treat the vendored `.js` as ESM and the UMD wrapper then has nothing to attach to. Don't "fix" that into a plain `import`; the alternative is a second 270KB copy on disk renamed `.cjs`. Nothing here is fetched from a CDN — the app makes zero external requests, which is what keeps the Mock provider a genuinely offline demo.

Untrusted text must never reach `.innerHTML` by any other route. The moderation editors prefill their textareas via the `.value` property, never innerHTML. Elsewhere in the frontend, config-derived strings (agent names, models, stances) are individually passed through `escapeHtml()` in template literals — follow that pattern when adding markup.

**The transcript is polymorphic.** `session.transcript` interleaves agent entries (no `type`; have `turn`/`agentIndex`) with moderator entries (`type: 'moderator'`; have `afterTurn`/`id`, no turn). `session.turn` counts agent statements only. Anything that iterates or counts the transcript must branch or filter on `e.type !== 'moderator'` — server: `messagesForSpeaker()`, `exportMarkdown()`, `_finish()`'s turn count; frontend: `rebuildTranscriptFromScratch()`, `updateRoundChrome()`, the `onTurnEnd` upsert, the finished-block count. Forgetting the branch shows up as a crash on `agents[undefined]` or as round ticks drifting after each injected note.

**The moderation gate exists twice.** `DebateSession.canModerate()` (server) and the `nextEnabled` expression in `updateControlsUI()` (frontend — it doubles as `state.canModerate` and the shell's `can-moderate` class) must express the same predicate: no turn in flight, not finished, not auto-running. The server is authoritative (the moderation routes answer 409); the frontend only shows/hides affordances. Change one, mirror the other.

**Role alternation is restored by merging, not by construction.** A moderator entry between two agent turns maps to a `user` message (`MODERATOR:` prefix via `moderatorInterjection()` — the same marker `finalRoundModeratorNote()` and the system-prompt moderator rule use), which lands next to the opponent's `user` message; `mergeConsecutiveRoles()` in `server/debate.js` joins those before any adapter sees the array. That merge is what keeps the README's "strictly alternating" adapter contract true. Moderator entries are always user-role, so the assistant-message count is invariant — `mock.js` selects its canned turn by counting `assistant` messages and depends on that.

**Provider adapters must yield text only.** The contract is in the README. The debate loop concatenates every yielded chunk directly into the transcript, so an adapter that yields reasoning traces, tool blocks, or JSON envelopes will corrupt both the display and the next turn's message history. Each adapter's file header records the specific API constraints it encodes (e.g. Anthropic rejects `temperature`/`top_p`/`top_k`; OpenAI needs `max_completion_tokens`, not `max_tokens`) — read the header before editing an adapter.

**Turn visuals are deliberately outside the `.innerHTML` invariant, not an extension of it.** The `<img src>` for a statement's visual is always constructed by the app as `/api/debates/:id/visuals/:turn`, never a string from model output; `alt` is assigned via the `.alt` property and any caption via `.textContent`. That is the whole reason no escaping is needed here. Do **not** add an `![]()` rule to `renderStatementHTML()`'s whitelist — the whitelist stays closed, and a model that emits image markdown should render it as literal text.

**The visual panel changes parents with the mode, and that is not optional.** In normal mode the `<figure>` sits inside the card under `.stmt-split`; in presentation mode `syncVisualMount()` reparents it to `.stmt-row`, beside the card, in the gutter. It cannot simply be positioned out of the card instead: `.stmt` carries a `clip-path` for its clipped corner (DESIGN_SPEC §4) and `clip-path` clips the whole subtree, so an overflowing child — absolutely positioned or not — is painted away. Anything that creates a statement row (`appendStatementRow()`) or flips the mode (`togglePresentationMode()`) has to call `syncVisualMount()` / `syncAllVisualMounts()`, or panels end up in the wrong parent for the current mode. The reparent is deliberately *not* a `rebuildTranscriptFromScratch()`, which would drop scroll position and the in-flight statement's caret. Paired with this, `renderVisualPanel()` sets `.has-visual` on the **row** (not the figure — `fig.className` is reassigned wholesale). That class carries both presentation-mode concessions a panel needs: it narrows the card to 58%, and it drops the row's 6% outboard padding so the panel — which is `flex: 1 1 0`, i.e. *all* the remaining width — reaches the transcript's page gutter. Without it a visuals-off debate would present in a needlessly narrow column and a lone card would stretch the full projector width.

**Image bytes never enter the transcript or the snapshot.** Only metadata rides on the entry (`entry.visual = { status, archetype, alt, mime, error }`); the bytes live in `DebateSession.visualBytes`, a `Map` keyed by turn, and reach the browser only through the dedicated route. `getSnapshot()` is re-sent to *every* reconnecting tab and `EventSource` auto-retries at arbitrary times, so base64 in the snapshot would push megabytes per reconnect. The same reason keeps bytes out of `exportJSON()`; `exportMarkdown()` emits an italic `*Visual: …*` caption rather than an `![](…)` link, because a relative API URL is dead inside a downloaded file. `exportHTML()` is the one place bytes are copied out — as `data:` URIs, inside a document the reader saves and keeps — and that is a per-request cost paid on a deliberate click, not something re-sent on every reconnect.

**A visual failure must never pause the debate.** This is the one deliberate exception to the "any provider error pauses the session" rule below. `_generateVisual()` owns its own try/catch and must never touch `lastError`, `state`, or `turnInFlight` — a rate-limited image API halting a live classroom is the worst failure mode this feature has. It marks `entry.visual.status = 'failed'`, broadcasts `visual_status`, and returns. Note that event is deliberately *not* named `error`: the SSE name collision described below makes that channel fragile.

**`server/visuals/mock.js` is load-bearing.** It needs no key, makes no network call, and emits a procedural SVG — it is what keeps a Mock-vs-Mock debate with visuals on a genuinely offline demo, the same zero-external-request property that vendoring KaTeX buys. `server/providers/mock.js` also has to answer the visual-director prompt with valid JSON, which couples it to `buildVisualDirectorPrompt()` in the same way `poolFor()` is coupled to the stance line — reword either prompt and the mock silently stops producing usable specs.

**The archetype list fixes the form, the model picks the subject.** The final image prompt is composed server-side as style preamble + `VISUAL_ARCHETYPES[archetype]` + the director model's prompt, so the model can never override the palette or the composition. The preamble's text-density rule is the main defense against garbled in-image labels, but it must stay *satisfiable*: it is a per-label budget ("at most three words per label, no more labels than the composition calls for, no repeats"), not a whole-image word count. An earlier six-word-total cap contradicted the multi-row archetype scaffolds outright, so the model discarded it — verified against `gpt-image-2`. Don't relax the rule, and don't make it impossible either.

**The caption is asked for in words and guarded in characters, and the two numbers must stay far apart.** The `<figcaption>` under a turn visual — in the app (`renderVisualPanel()`) and in the HTML export (`visualHTML()` in `server/export-html.js`) — is the director model's `alt` field verbatim, so *any* server-side shortening is visible on the projector. Models count words well and characters badly, so `buildVisualDirectorPrompt()` asks for the caption in `VISUAL_ALT_MAX_WORDS` (18) and quotes no character number at all, while `VISUAL_ALT_MAX_CHARS` (320) is a runaway guard sitting ~2.5x above what that ask produces. Tightening the cap toward the word count, or quoting the character number back to the model, is exactly how this was broken the first time: a 120-char cap that was simultaneously the number in the prompt and a bare `slice()` chopped roughly half of all captions mid-word. `parseDirectorReply()` clamps through `clampText()`, which cuts at a word boundary and appends an ellipsis, and reports what it shortened in `trimmed` so `_generateVisual()` can log it — a guard that fires on most turns means the prompt and the cap have drifted apart, not that the model misbehaved. The image `prompt` uses the same clamp with `sentenceFirst`, because a severed label instruction gets drawn into the figure as a fragment. `server/providers/mock.js`'s `magnitude` entry carries a deliberately over-cap 368-char alt: it is the only offline exercise of the trim path, so keep it long and keep every other canned alt well under.

**Presentation mode's sticky figure bounds itself, not just its image.** `#app-shell.presentation .stmt-row > .stmt-visual` is a `max-height:94vh` flex column, and the image (`flex:0 1 auto;min-height:0`) is the child that yields while the caption (`flex:0 0 auto`) never does. Capping only the image cannot work: the caption's height is the model's to choose, so image + caption is a sum nothing bounds, and a sticky box taller than the viewport pins its top and hides its own bottom — the caption. `min-height:0` is load-bearing; without it a flex item refuses to shrink below its content height. Any change to the caption's length budget or its font size has to be rechecked against this cap.

**The two visual model fields default from two different rosters.** The setup form's *image model* takes the `server/visuals/` adapter's `defaultModel` (openai → `gpt-image-2`), but the *director* runs over the ordinary text-provider contract — `_generateVisual()` calls `getProvider(agent.provider).stream()`, not the visual adapter — so `applyVisualProviderDefaults()` in `public/app.js` defaults it from the `server/providers/` adapter of the same vendor id (openai → `gpt-5.6-luna`, mock → `mock-debater-v1`), falling back to the visual adapter's default only for a vendor with no text adapter. That cross-roster lookup is why `init()` awaits `loadProviders()` **before** `loadVisualProviders()` instead of racing them in one `Promise.all` — with `state.providers` still empty the director field would silently fall back to the image model's name, which is exactly the bug this replaced.

## Session model

Sessions live in a plain `Map` in `server/index.js` and are never evicted. Consequences worth knowing:

- **A server restart drops every debate.** The frontend puts `?debate=<id>` in the URL and reconnects on load, so after a restart a refreshed tab gets a 404 from the SSE route with no recovery path.
- The `Map` grows unboundedly, and each session holds the full paper text plus transcript — plus, when visuals are on, every generated image in `visualBytes`. That last one is why `_generateVisual()` enforces a per-session byte budget and degrades to `status: 'skipped'` past it rather than growing without limit. Fine for classroom use; don't assume otherwise.
- Any provider error pauses the session rather than killing it: the error is stored in `lastError`, broadcast, and the state goes to `paused`.

**"Retry" and "Skip turn" in the error banner do the same thing.** Both POST to `/next` — there is no skip endpoint. Skip is presented as the calmer secondary action but re-runs the failed turn identically. Implementing a real skip means adding a server route, not a frontend change.

**SSE event-name collision:** the server sends a custom `error` event, and `EventSource` fires a native `error` event on connection failure. `connectSSE()` disambiguates by checking for `e.data` (only server events carry a payload). Preserve that check.

## Design

`design/DESIGN_SPEC.md` is authoritative for the UI, down to exact hex tokens, the type scale, and the two-column type sizing for presentation mode. `design/mockup.html` is the reference for exact inline SVG paths. The spec's core constraint drives most of its odd-looking choices: the app targets a classroom projector, which is why the theme is light parchment (a dark theme washes out under ambient light), why agent identity is encoded redundantly across five channels (side, hue, crest shape, clipped corner, text label), and why body type is 19px/28px. If you change visual behavior, read §1 for the rationale before overriding it.
